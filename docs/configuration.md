# 配置说明

## 项目配置

VibeSocial 按项目保存本地状态。第一次接入时，会为当前项目建立 `.vibesocial/`，不需要远程账号或数据库。

项目之间的草稿、审核历史和 Writing Memory 默认相互隔离。要处理另一个项目，应在那个项目的 Codex 上下文中启动 Skill，并重新选择或初始化。

## 写作风格

首次没有指定风格时使用默认风格。之后可以直接用自然语言提出“换一种风格”或提供自己的写作偏好。

风格配置只影响表达方式，不会把示例中的产品事实、姓名、日期或指标带入新草稿。

## 扫描范围

扫描前应明确选择项目和允许参考的开发记录范围。项目目录是默认且优先的扫描边界，Skill 不会自动扩展到父级 Git 工作区。Skill 只将经过筛选的事实摘要带入社交内容状态，不保存原始源码或原始 diff。

首次扫描会先执行轻量 dry run，统计项目文件、文档和 Git 规模，并估算 Token 范围和预计耗时。预计超过 50k tokens 会提醒，预计超过 100k tokens 必须得到明确确认。

## 微博发布配置

微博发布是可选步骤，需要本机安装并配置 `weibo-cli`。发布前会分别展示账号、CLI、开放平台和服务检查结果；无法读取凭据时不会直接判断为未登录，也不会要求重复登录。

VibeSocial Agent 不要求用户把 token 写进项目，也不会把账号配置写入 `.vibesocial/`。发布前会再次展示正文并等待用户明确确认。

## 本地状态

`.vibesocial/` 可能包含：

- 项目配置和扫描检查点
- 草稿、Social PR 和审核历史
- Writing Memory 和系列状态
- 只读性能记录
- 发布记录
- 各平台的本地发布偏好（例如微博标签）

该目录默认被 `.gitignore` 忽略。不要把它提交到公开仓库，也不要把包含私人内容的状态目录复制给其他人。
