# Writing styles

## Presets

- `casual-weibo`: direct opening, short paragraphs, concrete detail, conversational Chinese, restrained emoji.
- `developer-log`: chronological and precise, with technical detail translated into user impact.
- `storytelling`: problem, surprise, investigation, resolution, and takeaway.
- `product-update`: user problem, visible improvement, how to try it, and next question.
- `technical-explainer`: a concrete question followed by a clear mechanism and practical meaning.
- `default`: neutral, concise, and factual.

Avoid empty phrases such as “持续优化”, “进一步提升”, “赋能”, “从 0 到 1”, and “AI 时代” unless the user explicitly uses them.

## Custom profile

Describe observable form, not vague imitation. Include preferred length, paragraph rhythm, opening, ending, narrative structure, technical detail, punctuation, emoji habits, and forbidden expressions.

## Learned profile

Analyze at least three user-authorized samples when possible. Extract only stylistic features. Explicitly exclude all sample facts, metrics, dates, product claims, and named entities from reusable memory.

For stable project-specific rules and accumulated feedback, read `.vibesocial/writing-style.md`, `.vibesocial/anti-ai-patterns.md`, `.vibesocial/approved-examples.md`, `.vibesocial/feedback-log.md`, and `.vibesocial/series-state.md`. The generated project memory takes precedence over these preset descriptions.
