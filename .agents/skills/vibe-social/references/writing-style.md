# Stable writing memory

This file is the default memory copied into `.vibesocial/writing-style.md` when a project is initialized. Project-specific learning is written to `.vibesocial/`; this reference file is not a runtime log.

## CORE rules from explicit human feedback

- Keep one Weibo post around 150–200 Chinese characters when the material supports it. Compactness means information density, not cutting the article into fragments.
- Put a clear, stable series title on the first line.
- Give every sentence an information job; delete sentences whose removal does not change the meaning.
- Use an explicit first-person subject and put the actor before the action whenever possible.
- Write for ordinary readers, not for the developer's private implementation context. A reader should roughly understand what happened without importing a domain that the artifact never names.
- Prefer concrete object names, numbers, before/after changes, features, bugs, formulas, tests, frameworks, audits, and detours.
- Even a 200-character post needs a concrete event; avoid abstract development summaries.
- Allow conversational, incomplete, lightly note-like prose. Do not force a complete beginning–middle–end arc, a takeaway, or an uplifting conclusion into every post.
- Translate planning posts into an ordinary-reader goal instead of a developer command.
- Make a series move forward; do not keep several consecutive posts at the same abstract level.

## Learning policy

- Promote a rule only after explicit feedback, repeated evidence, or multiple approved drafts.
- Keep series rules in series memory and one-post constraints in the feedback log; do not globalize them.
- Read this memory before choosing a direction or drafting. Apply it as constraints, not as claims or facts.
